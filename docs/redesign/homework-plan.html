Underneath

One record per assignment

Not started→Working⇄Waiting for you→Ready→Handed in

or Stopped (with the reason and the saved answer). What the school says stays on the assignment; the screen shows both.

One session per assignment

  • Dot's work and your chat about it are one saved session, even after a restart.
  • Dot keeps going until it records a result: up to 3 nudges if it stops early, then it asks you. A watchdog catches stalls.
  • Button, chat and schedule start work the same way. Your own Start isn't blocked by stale details; Dot re-reads the page first.
  • The engine tells the screen when something changes, instead of the screen asking every second.

Permission checked 4 times? More than needed. Two checks: when work starts, and right before a submit (the only step that can't be undone). Changing a rule stops live work straight away.

Dot's method (general, any class or site)

  1. Understand everything: instructions, rubric, files, class note, related material.
  2. Decide where the work lives: school page, files, a vendor site, a repo.
  3. Do it the way the class expects.
  4. Check it: run code and tests, redo maths, go through the rubric.
  5. Put it where it goes, without submitting unless your rule allows.
  6. Hand it to you with proof, and say what it isn't sure about.

What Dot can do

School page (a plain click can't submit) · its own folder · a restricted terminal to run code · whole-document reading · new: the class's saved materials · talk to you or ask and wait · new: remember at any time, plus an end-of-run note · hand-off with proof · submit once, only if allowed · connected apps.

What Dot is told at the start

The assignment, your rule and preferences, files so far, plus new: the class name and note (grading, where work goes, your section), how your school works, the class's materials and exams, and related assignments.

Order of work

  1. Measure: a homework test on the fake school with many kinds of work (quiz, code with tests, essay with rubric, upload, vendor site, repo, one Dot can't do).
  2. Dot: method, context, class materials, keep-going, watchdog, memory. Measure again.
  3. One start and the two permission checks.
  4. One record and pushed updates.
  5. Screens: the numbered changes above, built in the real components and checked in the UI preview, plus the new icon and Dot from the characters plan.
  6. Real assignments, read-only (file-based ones in your folder), then your full test.

Decisions for you

  • Automatic mode: fix it, or ship only "you ask" for now?
  • Ready work waits for you, instead of a 15-minute window?
  • Inky: keep blue Inky on loading screens, or Dot everywhere? (Open in the characters plan.)
