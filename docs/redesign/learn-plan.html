Learn: a tutor that gets you the highest score on your real test.

This page and learn-concept.html are the contract. The mock fixes what each screen looks like and what data feeds each part. This page fixes the behaviour, the rules the app enforces, and the stories every build step is tested against.

Branch codex/studi-redesign-release. Written 2026-09-19. Replaces the Learn section of plan.html.

What we're building, and for whom

A student has an exam coming. They open Learn. Studi already knows the exam, what's on it, how much each topic is worth, and has their study guide and last quiz. It says what to study today, teaches it in small steps that make them think, checks their reasoning, remembers how they think, and tests them with questions shaped like their teacher's.

PrincipleWhat it means in the build
One selected goalHeadline, plan, topics, sources, Edit all read from selectedGoalId. Nothing on screen may describe a different goal. Every IPC call carries it and every response echoes it.
Grounded in their courseworkThe tutor is sent excerpts from the student's own sources every turn. A question based on them shows where it came from.
The student does the thinkingThe app runs the lesson phases and refuses lecturing: at most two statements before a question, predict before reveal, hints before answers.
Evidence, not vibesMastery moves only on unaided answers, graded by the app or a separate grader, never by the tutor's own say-so.
Add anything, from one placeOne intake box takes files, links, text, a sentence, or a scan request. Inky sorts it. The student never chooses between “source” and “exam”.
Quiet until neededOne filled button per screen. Sources and “Change or fix something” are closed by default and open in place. No edit forms: the student says what changed or taps one thing, and Inky does it.

Exams are the priority. Course goals and free topics (“learn Python”) use the same model and the same session machinery; they ship last and get no countdown and no readiness percent.

The workflow, end to end

Tell StudiDrop a syllabus, paste a link, type “stats midterm Friday”, or press Find my exams. Inky reads it and asks one confirm question.
GatherA read-only materials scan of that class finds the study guide, slides and past quizzes. The student can add files to any exam any time.
PlanThe app (not the model) picks today's topic: biggest gap for its share of the exam. Due misses come first.
SessionCheck, learn, practise, on your own, wrap up. 5 to 60 minutes, one topic.
Prove itTopic quizzes any time, a mock exam from two days out, built from their real assignments and tests.

Inside a lesson, when the student

A lesson is one topic through check, learn, practise, on your own, and wrap up (the phases in the Tutor section). The box under the lesson is always live. These are the cases a real 1-on-1 tutor handles, and ours must too.

Tutor

What it's sent every turn

{ goal:    { title, courseLabel, date, daysLeft, scopeNote },
  topic:   { title, style, weight, quotes },
  excerpts:[ { sourceTitle, role, locator, text } ],   // top chunks for this topic, ≤ 6k chars
  history: { lastResults, dueReviewItems },
  profile: [ relevant notes ],
  session: { phase, blocks, messages, minutesLeft } }

Prompt, in short: teach what this exam tests, in the formats the student's study guide and past tests use; spend time by weight and days left; when a block is based on an excerpt, pass its sourceRef. Free topics keep “teach from first principles”. Source text stays marked as untrusted data.

Phases (the app owns them)

Phase (label)Tools offeredLeaves whenCounts toward level
probe (Check)ask_choice, ask_typed, ask_explain. Due review items first.≥1 answeredCan lower only
teach (Learn)say, ask_predict, show, ask_explain≥1 student responseNo
guided (Practise)ask_typed with hints, ask_explain, show≥2 answeredCan lower only

  • The model asks to move on with tutor_advance. The repository checks the exit condition and the tool list is rebuilt for the new phase.
  • openBlock rejects a third tutor_say in a row and any tool outside the phase. The error text tells the model what to do instead.
  • A probe answered correctly with confidence lets the tutor skip teach. A short session (5 min) is probe then independent.
  • Level moves at most one step per session, up only with a correct unaided answer.

Style by topic

topic.styleHow teach and guided run
conceptual (maths, physics, stats)Puzzle first. ask_predict before any reveal. A scene to explore. The smallest nudge that unblocks. The student states the rule; then the tutor names it.
factual (terms, dates, anatomy)Retrieval before reading. Short reads. Misses come back later in the same session.
procedural (code, accounting, lab methods)Worked example, then the same shape with steps removed, then alone.

Grading

Explain and predict answers go to a separate one-shot grader session: rubric (written before the answer), the answer, the source excerpt. It returns pass or fail per rubric line and a misconception if it sees one. The tutor gets the verdict as the tool result and cannot change it, the same way typed verdicts work today (learn-records.ts:352).

Missed questions

Every wrong independent answer becomes a ReviewItem due in 1, then 3, then 7 days, never past the exam date. The next probe pulls due items first. This replaces the fixed three-day recap in planLearn.

Practice tests and quizzes

  • A background job per exam goal, rerun when sources change, writes QuizItems: from past_test, assignment and study_guide chunks first, same formats and difficulty, each with its sourceRef.
  • A second pass answers each item cold. If it disagrees with the key, the item is dropped. Only verified items are served.
  • A goal with no such sources still gets items, and the result screen says they aren't based on the student's own tests.
  • Topic quiz: 5 minutes, from the goal detail. Full practice exam: timed, topic weights respected, available any time. Two days before the exam Inky suggests it in the Today row. Both run as sessions with no teaching, graded by the app and the grader, feeding mastery and review items.

Agent runtime and test harness

Runtime

  • Same shape as today: a Pi session with a raw system prompt, tools executed by the app, state rebuilt from SQLite on every launch (tutor-coordinator.ts #run).
  • Tools are created per launch from session.phase; the six-tool boundary check becomes a per-phase boundary check.
  • Grader, intake classifier and item-bank builder are single-purpose sessions through createLearningSession, like extraction.
  • Delete the dead {kind:"tutor"} agent target, roles/tutor pack and the not_supported phase.

How each kind of behaviour is tested

Deterministic: node tests on the repository and planner, no modelUI journey: preview fixtures driven like release-learning.journey.mjsSimulated student: a model plays a persona against the real tutor, a judge scores the transcriptLive: real account, real school or fake LMS, by hand or the QA skill

Simulated students live in agent-harness/tutor/. A persona file says what the student knows, one planted misconception, and how they behave (guesses when stuck, terse, asks for the answer). The judge returns yes or no with a quoted line for each check in the story. Run each persona three times; a story passes at three of three.

The fake LMS gains, per course: a syllabus page, a study guide PDF, a slides page, and a graded past quiz, so the materials scan runs end to end.
