What works

Studi can durably queue permitted assignments, order them by manual priority and deadline, steer one next, cancel work, acquire one browser-worker lease, and recover the same state after restart.

What stayed out

The runtime path

A task enters through the coordinator

The coordinator loads the stored task and assignment. It never accepts course or pattern provenance from the agent.

Stored rules decide eligibility

Confirmed pattern matches come from SQLite. The existing permission resolver applies assignment, pattern, course, and global specificity. A denied assignment never enters the queue.

SQLite owns ordering

The durable row stores priority, deadline, enqueue time, and the resolved permission receipt. Queries derive the next item. There is no second in-memory queue.

One lease owns the browser

A singleton SQLite key is the atomic arbiter. A second start fails while the first worker owns the lease, even after the store reopens.

Pi receives narrow manager tools

One persistent manager AgentSession can inspect, steer, or cancel queue entries. Worker sessions are explicit children. Neither session receives shell or filesystem tools.

Restart reconciles durable truth

Interrupted acquisition releases. Active work resumes its saved Pi worker session only when the task is still working. Stale rows are removed and orphaned queued tasks are rebuilt or cancelled after fresh permission resolution.
