1

Consumers receive a Pi-free contract

Full shared/agent-runtime.ts · 97 linesRuntime interfaces

unknown Pi activity → validated AgentRunEvent → manager, desk, logs, or tests

The shared union names only product-relevant activity: text, tool start/finish, retry, compaction, abort, and terminal. Provider status has three states and a small login-method enum. No Pi event type, credential path, or provider error is part of the consumer API.

export const AgentRunEventSchema = z.union([
  AgentTextEventSchema,
  AgentToolStartedEventSchema,
  AgentToolFinishedEventSchema,
  AgentRetryEventSchema,
  AgentCompactionEventSchema,
  AgentAbortedEventSchema,
  AgentTerminalEventSchema,
]);

Boundary rule: later packages can depend on Studi concepts without learning Pi's internal event vocabulary.

The runtime creates the one shared Pi environment

Full runtime from PiAgentRuntime

PiAgentRuntime.create → credential store + model registry → local Pi paths → runtime ready

The runtime owns Pi setup once. Production may use Pi's normal registry and authentication stores; tests inject a deterministic model runtime. Resource discovery is explicitly empty so a user's unrelated Pi extensions, skills, templates, themes, or context files cannot silently alter Studi behavior.

Session construction proves the tool boundary

Pi session factory

persistent/open session manager → Pi createAgentSession → exact tool assertion → wrapper

WP-03 registers one harmless tool. Pi's built-ins are disabled, only studi_probe is configured, and the runtime checks the active session after construction. If a future SDK update changes the meaning of those options, startup fails instead of exposing shell or filesystem access.

const result = await createAgentSession({
  ...options,
  noTools: "all",
  customTools: [studiProbeTool],
  tools: ["studi_probe"],
});
assertExactTools(result.session, ["studi_probe"]);

What comes later: WP-05 will replace this probe with policy-aware browser tools. WP-03 does not prebuild that framework.

The wrapper is the sole live-session owner

Full PiBackedAgentSession

prompt / abort / compact → underlying Pi session → one subscription → Studi listeners

The wrapper keeps one Pi session, one Pi unsubscribe function, one normalizer, and a set of Studi listeners. It emits a fallback terminal event only if Pi did not already provide one. Disposal is idempotent and delegates resource cleanup to Pi.

subscribe(listener) {
  this.listeners.add(listener);
  return () => this.listeners.delete(listener);
}

#emit(event) {
  const parsed = AgentRunEventSchema.parse(event);
  for (const listener of this.listeners) listener(parsed);
}

The normalizer translates behavior, not implementation detail

Full PiEventNormalizer

Pi event → update minimal turn state → zero or one normalized event → Zod validation

The normalizer remembers only what terminal reporting needs and whether abort was already emitted. Tool names and text cross the boundary; retry and compaction errors do not. Fixed Studi messages prevent tokens, paths, headers, or upstream details from leaking through status UI or analytics.

case "auto_retry_end":
  return [{
    type: "retry",
    phase: "finished",
    succeeded: event.success,
    reason: event.success ? undefined : SAFE_RETRY_FAILURE,
  }];

Replacement is transactional at the object boundary

Real session replacement

create next → if successful, unsubscribe old → swap → reset → subscribe next → dispose old

The old session remains usable if creation fails. After a successful swap, listeners registered by Studi remain in the wrapper and receive resumed events. Only the Pi subscription changes.

const next = await this.createPiSession(target);
const previous = this.session;
this.unsubscribePi();
this.session = next;
this.normalizer.reset();
this.bindPiSession();
previous.dispose();

Ownership result: there is never a moment when two Pi sessions can publish through the same wrapper.

7

Provider readiness leaves credentials behind

Provider status boundary

provider ID → registered Pi provider → ModelRuntime.checkAuth → parsed, fixed ProviderStatus

Known providers may return safe display identity and supported login methods. Unknown or failed checks return fixed Studi reasons. Raw inputs, credential sources, Windows paths, tokens, and upstream errors are not forwarded.

8

The fake matches the boundary, not Pi internals

Full FakeAgentRuntimeFull focused tests · 328 lines

The fake implements the same runtime and session interfaces, validates injected events, retains listeners across replacement, and supports prompt, abort, and compaction. Its default turn matches the real deterministic Pi turn byte for byte.

Why it is beside the adapter: parity is easy to review today. The independent reviewer recommended splitting only when a later package adds a second control flow.
