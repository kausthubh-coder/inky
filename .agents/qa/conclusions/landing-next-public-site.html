Landing · conclusion

The landing mock now ships as the Next.js site in landing/.

A visitor gets the approved page: headline, one-sentence explanation, campus-email form and trust line on the first screen; a four-step Studi demo; six trust promises; supported school systems; the yellow waitlist card; FAQ. Both forms write one normalized row through Convex. Clerk mounts around Convex when its key exists and never gates the page.

Flow

  1. app/page.tsx renders the client LandingPage. Fonts load through next/font; the only stylesheet is app/globals.css, a direct port of the mock’s CSS with the Inky rig included.
  2. Demo owns one beat index plus paused, asking, autoplay, and visible. Beats are a constant table; the rail, titlebar controls, week board, and reply buttons all call go(). Autoplay stops on the first click and while the scene is off-screen. ?beat=N opens a step for review.
  3. The typing effect keeps its index in a ref, so Takeover pauses mid-sentence and “keep going” resumes there instead of restarting.
  4. WaitlistForm validates with the browser’s email field, then calls api.waitlist.join. Convex normalizes, validates again, checks the by_email index, and inserts only new rows. Success is lifted to LandingPage so both forms swap to the same “You’re on the list” state.
  5. Any server failure shows Inky’s “Something on my end hiccuped” line; server error text is never surfaced.
  6. app/providers.tsx picks ConvexProviderWithClerk when NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY exists, plain ConvexProvider otherwise, and no provider when Convex is unset.
  7. /mission is a static server page so the nav link no longer dead-ends. app/icon.svg supplies the favicon.

Why this stayed small

One component file, one stylesheet, one state machine, no UI or animation library, no API route, no localStorage fallback, no sign-in surface. The old scroll-hijack renderer and its 780-line stylesheet were deleted rather than kept beside the new page. The shared Inky renderer gained only the steering state the demo needed.

  • Headless Chrome renders of the production build at 1440 and 390 px match the approved mock at the fold, the four demo beats, trust grid, waitlist card, and FAQ.
  • puppeteer-core drive against next start: ?beat=3 hydrates with step 4 pressed; clicking step 3 starts typing (27 → 118 chars in 2 s); Takeover shows “All yours.” and freezes the count at 120; “keep going” resumes to 143; the quiz card shows “Cute. That one’s a you problem.”; an invalid backend yields the friendly error, not a crash. No page errors besides the favicon 404 that app/icon.svg now fixes.
  • Vercel project inky built commit 3a1bcd8 READY as a protected preview; fetched through a share link it serves the new page with NEXT_PUBLIC_CONVEX_URL inlined.

Blocked outside this VM

The Convex deployment behind NEXT_PUBLIC_CONVEX_URL answers account:bootstrap but not waitlist:join: its functions predate the waitlist module and this VM has no Convex credentials to push them. Until npx convex deploy (or npx convex dev) runs from the repo root, the live form shows the friendly error. Vercel has no NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY, so Clerk is not mounted on the preview.
