Landing · conclusion

The landing mock now ships as the Next.js site in landing/.

A visitor lands on a full-screen desktop: wallpaper, dock, and the Studi window with Inky greeting and autoplaying the tour under a floating pill nav. Scrolling shrinks that desktop into a bordered box while the headline, one-sentence explanation, and email form fade in above it; then the page continues with outcome-led features, a chatbot comparison, six trust promises, school systems, the yellow waitlist card, and FAQ. Both forms write one normalized row through Convex. Clerk mounts around Convex when its key exists and never gates the page.

Flow

  1. app/page.tsx renders the client LandingPage. Fonts load through next/font; the only stylesheet is app/globals.css, which includes the Inky rig.
  2. useDesktopShrink reads native scroll inside a pin that is 190vh tall with a 100vh sticky child, eases it, and writes one --p variable (0 desktop, 1 box) plus the measured hero height. Every visual interpolation is CSS calc() on --p: nav inset and radius, sticky padding, hero height and opacity, scene border and radius, window size, dock/rail crossfade. Phones and reduced motion hold --p at 1 and unpin.
  3. SiteNav highlights the section in view with one IntersectionObserver and exposes a menu toggle on phones. One waitlist action: Get a seat.
  4. Demo owns one beat index plus paused, asking, autoplay, and visible. Beats are a constant table; the rail, titlebar controls, week board, and reply buttons all call go(). Autoplay stops on the first click and while the scene is off-screen. ?beat=N opens a step for review.
  5. The typing effect keeps its index in a ref, so Takeover pauses mid-sentence and “keep going” resumes there instead of restarting.
  6. WaitlistForm validates with the browser’s email field, then calls api.waitlist.join. Convex normalizes, validates again, checks the by_email index, and inserts only new rows. Success is lifted to LandingPage so both forms swap to the same “You’re on the list” state.
  7. Any server failure shows Inky’s “Something on my end hiccuped” line; server error text is never surfaced.
  8. app/providers.tsx picks ConvexProviderWithClerk when NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY exists, plain ConvexProvider otherwise, and no provider when Convex is unset.
  9. /mission is a static server page so the nav link no longer dead-ends. app/icon.svg supplies the favicon.

Why this stayed small

One component file, one stylesheet, one state machine, no UI or animation library, no API route, no localStorage fallback, no sign-in surface. The old scroll-hijack renderer and its 780-line stylesheet were deleted rather than kept beside the new page. The shared Inky renderer gained only the steering state the demo needed.

Blocked outside this VM

The Convex deployment behind NEXT_PUBLIC_CONVEX_URL answers account:bootstrap but not waitlist:join: its functions predate the waitlist module and this VM has no Convex credentials to push them. Until npx convex deploy (or npx convex dev) runs from the repo root, the live form shows the friendly error. Vercel has no NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY, so Clerk is not mounted on the preview.
