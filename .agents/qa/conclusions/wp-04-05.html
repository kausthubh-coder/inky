What works

Studi owns one visible persistent WebContentsView. Pi authenticates through openai-codex and receives eight named browser tools that operate that exact view.

What stayed out

No fake LMS, Playwright browser, raw CDP tool, LMS-specific script, manager queue, scheduler, memory system, or automatic submission.

The real path

The user connects Codex

Studi opens Pi's built-in OAuth flow in the system browser and stores the provider credential in its app-owned Pi directory.

The user opens Moodle

Electron loads the school URL into one visible view using persist:studi-school. Passwords and cookies stay in Chromium.

The controller observes the page

CDP returns a bounded accessibility snapshot with a revision and temporary element refs. A page change invalidates old refs.

Pi uses Studi tools

The real Pi session can snapshot, navigate, click, type, select, press a key, wait, or explicitly submit. It never receives raw debugger access.

Submission stays separate

Ordinary click and Enter reject controls that appear to submit. browser_submit requires an explicit confirmation value.

The result returns to the sidebar

The real agent inspected CSC 217 in the visible browser and returned the course identity, Moodle platform, URL, navigation, and notification evidence.
