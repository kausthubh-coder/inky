1

Electron chooses the owned root

Full electron/main.tsFull store.ts · 69 lines

app.getPath("userData") → studi-data → openLocalStore(root)

The main process owns the store. The renderer never receives a database handle or generic storage method. LocalStore is the small composition root that connects one database to five repositories and the artifact store.

export async function openLocalStore(rootDirectory, options = {}) {
  await recoverInterruptedRestore(rootDirectory, options.failureInjector);
  return new LocalStore(rootDirectory, options);
}

Why this matters: recovery runs before SQLite opens. A half-finished directory swap cannot be mistaken for a normal store.

2

The database proves it is usable

Full database.ts · 455 lines

open handle → PRAGMA quick_check → schema version → migration or shape check

A fresh path runs migration 1 in one transaction. An existing path must report exactly the supported version and required tables, columns, keys, and indexes. Corrupt or future-version files fail closed; they are not replaced with an empty database.

this.handle.exec("BEGIN IMMEDIATE");
try {
  const result = operation();
  this.handle.exec("COMMIT");
  return result;
} catch (error) {
  this.handle.exec("ROLLBACK");
  throw error;
}

The migration registry and version-1 schema descriptor live beside the driver because they change together. There is no ORM or generic migration engine.

A task event and projection are one commit

Task repositoryTask and event contracts

validate event + projection → check sequence/revision → insert event → update projection → commit

TaskRepository.append never permits an event without its corresponding current state. Creation expects no prior projection and sequence zero. Transitions expect the exact prior revision and next sequence.

return this.database.transaction(() => {
  this.assertCurrentState(event, expectedRevision);
  insertEvent.run(/* canonical event */);
  this.database.injectFailure("task_before_projection");
  updateProjection.run(/* canonical task */);
  return projection;
});

An injected failure between the two statements proves rollback removes both sides.

5

Replay reconstructs truth from history

Full replayTaskEvents

task_created at sequence 0 → legal transition 1 → legal transition 2 → final task

Replay checks task identity, assignment identity, sequence, state, revision, and timestamps as it applies events. rebuildProjection uses this same function. Backup validation also reuses it, so there is one task state machine rather than a second backup-only interpretation.

const replayed = replayTaskEvents(taskId, events);
if (storedProjection) {
  assert.deepEqual(storedProjection, replayed);
}

Result: a projection is convenient, not irreplaceable. An inconsistent history cannot enter through restore.

A Markdown artifact replaces atomically

Full artifacts.ts · 263 linesArtifact contracts · 44 lines

validate kind + ID + frontmatter → write sibling temp → sync → rename → read and parse

Only four known directories exist. IDs are one safe path segment. YAML uses the core schema, unique keys, no aliases, and strict Zod frontmatter. Root, kind-directory, and child links or junctions are rejected with lstat.

await temporaryHandle.writeFile(serialized, "utf8");
await temporaryHandle.sync();
await temporaryHandle.close();
await rename(temporaryPath, targetPath);

A failed pre-rename write leaves the previous target readable and cleans only its owned temporary file.

A backup must be meaningful, not merely openable

Full backup.ts · 532 linesPersisted-record audit

SQLite backup API + plain artifact copy → schema shape → every record → every query column → every task history → every projection → every artifact

validateDataRoot is the restore gate. It rejected all failures found during the manager loop: missing tables, bad canonical records, mismatched query columns, invalid task histories, divergent projections, malformed Markdown, and artifact links.

const health = database.health();
validatePersistedRecords(database);
const artifacts = new ArtifactStore(artifactRoot, database);
const artifactCount = await artifacts.validateAll();

Important distinction: PRAGMA quick_check proves SQLite structure is internally consistent. It does not prove Studi can understand the stored product data. Both checks are necessary.

8

Restore has one commit point

Restore entryInterrupted recoveryAtomic journal write

validate source → atomically publish intent → stage → validate stage → move roots → validate target → best-effort cleanup

The journal is written to an exact temporary sibling, synced, and renamed before the fixed staging directory is used. Existing-target restores keep the old root until the replacement validates. A live failure rolls back before it rejects.

For a fresh target, the journal carries one small absence marker. If the process dies before commit, recovery removes the incomplete exact-owned stage and journal. It never installs a partially copied database without its artifacts. A later restore can retry.

const targetWasAbsent = !(await pathExists(target));
await writeRestoreJournal(paths, targetWasAbsent);
// stage and validate
await rename(paths.next, target);
const installed = await validateDataRoot(target); // commit point
await finishValidTargetRestore(paths, options.failureInjector);

Windows rule: directory rename always targets an absent exact sibling. The code never assumes an in-place directory replacement will work.
