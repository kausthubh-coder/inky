The product in one sentence

approved student → real Pi agent → one visible school browser
  → evidence-backed assignments → permission-filtered durable queue
  → work / handoff / review → submission receipt or Markdown fallback
  → dashboard + desk + library explain the same local truth

What is real

A packaged Windows app, dedicated Clerk test identity, Convex beta entitlement, user-provided Codex subscription, persistent browser profile, versioned SQLite, Markdown artifacts, close-to-tray lifecycle, and a live NC State Moodle handoff.

What is not claimed

No tutoring product, billing checkout, native installer, auto-updater, signing pipeline, coordinated devices, mobile app, generic office workspace, or real coursework submission. The final signed-in Moodle continuation is still pending.

The user journey

Account and provider

Clerk proves identity, Convex proves beta access/credits, safeStorage restores the credential, and Pi connects to the student's existing Codex subscription.

School onboarding

The student gives a school root and permissions, signs in only inside the visible browser, and chooses manual/daily/weekly scanning.

Evidence-backed discovery

The scan agent navigates with general browser tools. Narrow recording tools accept only facts visible in current snapshots and persist concise provenance.

Durable work selection

Verified assignments receive one stable task origin. Fresh permission resolution decides queue eligibility; deadline and user priority decide order.

Visible execution and handoff

One Pi worker leases the one school browser. Login, CAPTCHA, unsupported work, ambiguity, or exhausted recovery becomes a student handoff.

Review, submit, or preserve

Attempt-only work remains on the page for review. Expiry/restart saves Markdown first. Auto-submit requires fresh permission, a fresh unique control, and newly observed confirmation.

One understandable product surface

The weekly dashboard, active-only desk, library, settings, notifications, telemetry inspector, and diagnostics all project Electron-owned truth.

Private-beta delivery

Forge packages the same runtime. Immutable code stays in the package; database, artifacts, cookies, sessions, preferences, and credentials remain in userData.

Why the architecture stays maintainable

Each expensive effect has one owner: auth, telemetry, browser, scan, queue, assignment execution, lifecycle, storage, diagnostics. New packages reuse those owners instead of adding parallel queues, state stores, workflow engines, evidence services, or provider frameworks.

How the build loop changed the code

The implementer wrote only package behavior and useful boundary checks. The tester exercised the real app without editing production. The reviewer looked for elegant ownership and subtraction. Only reproduced failures caused repair passes.
