Studi can measure the product without recording the student’s school.

PostHog identity, product events, masked renderer replay, opt-out, and a local inspector are contained behind one allowlisted telemetry boundary. The embedded school browser is deliberately outside that boundary.

Code walkthroughDossierLive retestMaster plan

What is captured

Typed product outcomes such as onboarding, scans, queue activity, handoffs, review, errors, model usage, and tool timing. Properties are allowlisted by event schema before dispatch.

What is excluded

No school URL, page HTML, prompt, answer, cookie, token, authorization header, password, raw tool payload, or embedded-browser replay.

Privacy flow

Consent comes first

Analytics and replay begin disabled. Preferences persist locally and can stop capture immediately.

Identity stays coherent

Approved Clerk identity rotates both main and renderer telemetry to the same subject. Sign-out resets both.

Events pass an allowlist

Each event has an explicit property schema. A second scrubber rejects secret-shaped strings and unsupported fields.

Replay sees only Studi

The renderer integration masks text and inputs. PostHog is never injected into the separate school WebContentsView.
