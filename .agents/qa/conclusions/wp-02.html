Delivered

One local store owns assignments, rules, runs, immutable task events, rebuildable task projections, and four typed Markdown artifact kinds. Reads and writes cross WP-01 schemas.

Kept small

No ORM, cloud sync, renderer database API, prototype import, generic query builder, or speculative storage framework. Electron's bundled SQLite sits behind one driver.

The runtime journey

Electron opens one owned data root

openLocalStore recovers interrupted restore state, opens studi.sqlite3, runs integrity and version checks, then composes the repositories and artifact store.

Records are validated twice

Repositories parse WP-01 schemas before a write and again after a read. Canonical JSON preserves the whole record; explicit columns support the few current queries.

Task history and current state commit together

A task event and its projection update share one BEGIN IMMEDIATE transaction. Revision and sequence checks stop stale or skipped writes before commit.

Projection replay proves history is sufficient

Replay requires a sequence-zero task_created event and every legal transition after it. A deleted projection can be rebuilt; an invalid stream is rejected.

Editable context stays in Markdown

Preferences, memories, workflows, and answer fallbacks use strict versioned frontmatter. Writes sync a sibling temporary file before rename. Links and path traversal are rejected.

Restore validates before it moves active data

The backup must have the required schema, readable records, consistent query columns, replayable task histories, matching projections, and a plain artifact tree.

A small journal makes crashes recoverable

Restore intent is atomically published before staging. Existing-target failures preserve the last good root. Fresh-target failures discard incomplete owned staging and allow a clean retry.
