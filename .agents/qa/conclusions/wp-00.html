Result

Cycle 1 exposed two real defects. Cycle 2 removed the remaining legacy production inputs and made invalid Electron test configuration terminate safely. Independent testing passed every gate. The final review found no blocker.

Boundary

This package deliberately adds no school scan, browser automation, Pi runtime, database, auth, scheduling, or finished dashboard. It proves the base those systems will use.

How the code runs

The command builds both halves

package.json compiles Electron with strict TypeScript, builds the React renderer with Vite, then prepares the unchanged Sites handoff.

Electron validates its launch mode

electron/main.ts rejects unsafe self-test profile paths before Electron becomes ready. A normal or valid isolated run continues.

The main process creates one isolated window

The window has no Node integration, uses context isolation and sandboxing, blocks popup creation, and prevents renderer-driven navigation.

The preload opens one narrow door

electron/preload.cts publishes one frozen method, getRuntimeInfo(), over one fixed IPC channel. The renderer cannot choose arbitrary channels.

React reports the real environment

src/app/StudiApp.tsx mounts one app-ready marker. In Electron it displays returned runtime versions. In a browser preview it truthfully says the desktop bridge is absent.

The self-test crosses the real boundary

Electron loads the compiled renderer, finds the marker, calls through the preload, checks four runtime values, exits, and lets the runner remove only the owned temporary profile.

Startup and self-test failures begin in electron/main.ts. Bridge failures cross electron/preload.cts and src/platform/studi-api.ts. Renderer readiness ends at StudiApp.tsx. The focused reproductions live in tests/electron-self-test-runner.mjs.

Known limits

Only Windows was exercised. The test window is hidden and isolated. A visible normal-profile smoke, packaged development-URL restrictions, and explicit renderer-load failure handling remain follow-ups.
