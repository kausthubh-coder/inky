Delivered

PiAgentRuntime owns real Pi construction and provider checks. Each session owns one Pi session and exposes only normalized Studi events. FakeAgentRuntime implements that same consumer contract.

Deliberately omitted

No browser tools, manager/worker framework, UI, queue, memory, generic provider abstraction, transcript database, shell or filesystem tool, or paid-provider test.

The runtime journey

A caller asks for a session

PiAgentRuntime supplies Pi with its local agent directory, model runtime, persistence target, and one explicit custom tool.

Pi starts locked down

Resource discovery is empty, noTools: "all" removes built-ins, and a post-create assertion requires both configured and active tools to equal studi_probe.

One wrapper owns one live session

PiBackedAgentSession starts prompts, aborts work, requests compaction, receives Pi events, and fans normalized events to Studi listeners.

Pi detail stops at the normalizer

Text, tool, retry, compaction, abort, and terminal activity becomes one validated AgentRunEvent union. Upstream error and credential-shaped text is replaced with fixed Studi messages.

Replacement preserves the consumer

The next Pi session is created first. Only after success does the wrapper rebind its Pi subscription, keep existing Studi listeners, and dispose the old session.

The fake proves downstream code cheaply

The deterministic fake emits the same public turn as the real Pi session, so later packages can test orchestration without network calls or a second interface.
