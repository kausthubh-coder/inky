What works

Closing the window keeps Studi alive. Daily and weekly scans persist across restart. Exactly one scan or assignment owns the school browser. Attempt-only work remains for review, expired review saves Markdown, and auto-submit needs fresh permission plus newly observed confirmation.

What stayed out

No cloud account, analytics, billing, packaging, full dashboard, tutoring, CAD/Blender automation, or LMS-specific executor was added. Real Moodle submission remains outside testing.

Lifecycle flow

Electron owns the process

A single-instance lock rejects duplicate app processes. Closing hides the main window. Tray Open restores it; explicit Quit ends it.

The next wake is durable

SQLite stores cadence, local time, timezone, next occurrence, and the last claim. A daily occurrence that has passed advances to the next local day, including DST handling.

One owner protects the browser

The same ownership object guards assignment start/resume and every manual, resumed, replayed, or scheduled scan entry. A due scan remains unclaimed while assignment review owns the page.

Restart reconciles truth

Review deadlines and execution state reopen from SQLite. Chromium form state is not promised across process restart: Studi saves the answer Markdown and enters an explicit student handoff.

Assignment flow

The manager leases one task

Stored permission is resolved before the task starts. The existing manager lease and Pi worker remain the only queue and worker owners.

The agent changes the visible page

The worker receives the assignment, rules, budget, and browser tools. Unsupported work, login, CAPTCHA, and two failed recovery plans become honest handoffs.

Attempt-only starts review

The verified page stays open, the lease remains held, a notification is recorded, and the configured review deadline starts. Expiry writes the answer artifact before releasing work.

Auto-submit proves a new result

Permission is resolved again. Studi refreshes and uniquely rebinds the control, rejects confirmation already visible, records the one effect, clicks once, and writes a receipt only if the expected confirmation newly appears afterward.
