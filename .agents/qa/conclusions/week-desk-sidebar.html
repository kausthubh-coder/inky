WP-14

The week board keeps the student; Inky’s desk slides in beside it

What the student gets

This week stays the home screen. A week card opens a paper sidebar with the checked assignment, a start action, earlier Inky work, and a talk field. Inky’s desk is a chrome control for the same sidebar on the live school page. The greeting Inky matches the run and reopens the desk. Library is gone. Feedback is a small week note and a Settings note.

How control moves

Renderer panel state is closed, assignment, or desk. One derived value, showingLiveDesk, means the open sidebar is the live run. That value shows the school page, widens the drawer, and shrinks the week board. startAssignment refuses before enqueue if a run is already live. Talk and task detail stay keyed to the open assignment. The guest view uses the measured sidebar slot, not guessed coordinates.

Why this stays small

The full-page desk and Library screen are gone. Settings still writes the same preferences, rules, schedule, and telemetry. No second queue or second Inky machine was added.

Proof

Typecheck, contract tests, and the Electron self-test are the gates. A start-while-busy store dump proves a second startAssignment leaves the waiting task discovered and the queue unchanged. Vite ?preview is not the desk proof: it never runs the real start or layout path.

Debug first

If the school page misses the sidebar, inspect the renderer slot data-school-slot and the last setBrowserLayout bounds. If start mutates the queue without a live run, the busy guard in startSelectedAssignment did not run first.
