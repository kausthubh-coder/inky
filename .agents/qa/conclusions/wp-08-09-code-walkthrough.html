Shared schemas define the durable lifecycle language

Full shared/lifecycle.ts · 133 lines

schedule · execution phase · recovery attempt · notification intent · submission receipt

The schemas keep task state and execution detail separate. The task event stream still says whether work is queued, under review, submitted, preserved, or failed. Lifecycle records hold the timing and evidence needed to explain how it got there.

2

SQLite stores everything that must survive restart

Versioned databaseLifecycle repository · 214 lines

validated canonical JSON + indexed query columns → fail-closed reads

Schedules, executions, attempts, notification intents, and receipts are written before their side effects matter. Indexed columns are checked against the validated record, so a query cannot silently disagree with canonical state.

3

One small owner guards the visible school browser

Full work-ownership.ts · 86 linesOne shared instance in the composition root

durable manager lease + current scan state + short in-process reservation → start or a specific busy error

The same object is injected into the assignment coordinator, scan coordinator, and app kernel. Its reservation closes the asynchronous gap before SQLite records exist; durable records cover restart. There is no second browser queue.

4

The schedule calculator preserves local intent

nextScheduleRun

Daily and weekly schedules are expressed in the student's timezone. A valid occurrence that already passed advances to the next day or week. The DST fallback is used only when the requested local minute genuinely does not exist.

5

The app kernel turns time into one claimed scan

reconcileFull kernel · 252 lines

timer wakes → reconcile expired review → reserve browser for scan → claim due occurrence → run scan → record notification → arm next timer

If an assignment owns the browser, the scan reservation fails before the occurrence is claimed. The same due time remains for the next reconciliation. Sleep across several occurrences still coalesces into one claim and one next future time.

6

Electron owns hide, tray, and explicit quit

Kernel initializationDesktop composition root

The kernel intercepts window close and hides the window without disposing coordinators. Tray Open focuses it, Pause changes the stored schedule state, and Quit removes the close interception before ending the app. Notification clicks route to a typed task or scan target.

7

An assignment starts through existing queue ownership

Assignment startExisting manager and lease

browser reservation → manager selects deadline queue → fresh permission → durable lease → child Pi worker → execution checkpoint

The new coordinator does not own another queue. It asks the manager to lease the same task, then supplies the Pi worker with stored assignment context, preferences, task budget, browser tools, and six narrow execution tools.

8

Review keeps the page; expiry preserves answers first

Start reviewPreserve fallback

fresh page evidence + answer snapshot → ready_review + deadline → student submits or artifact write → lease release

During the live process, the page and lease stay intact. If time expires, the Markdown write completes before the task becomes preserved. If the process restarts, Studi does not pretend Chromium restored form state: it saves the answers and enters a handoff.

9

Auto-submit proves change, not merely a click

#submitBrowser controller

resolve permission again → fresh snapshot → uniquely rebind control → confirmation absent → mark one attempt → click once → confirmation newly present → receipt

The pre-submit snapshot deliberately invalidates the old DOM ref, so the browser controller matches the same unique role and accessible name in that fresh snapshot. Pre-existing confirmation stops before any effect marker or click. After the effect begins, any ambiguity becomes a student handoff and never a blind retry.

10

The renderer projects state without owning it

Full StudiApp.tsx · 282 linesTyped IPC contract

The lifecycle card shows schedule state, active work, attempts, review countdown, handoff reason, receipt, and saved-answer action. Buttons invoke typed Electron commands; React cannot write schedules, execution phases, leases, evidence, or receipts directly.

Debug order: visible-browser owner → wake reconciliation → execution phase → manager lease → durable lifecycle row → browser snapshot and page. For submission, inspect fresh permission, refreshed control identity, pre-effect text, the single attempt marker, and post-effect text in that order.
