WP-14

Keep the week board, open Inky’s desk beside it

The student stays on This week. Assignments, Inky, and Inky’s desk share one sidebar. Library leaves chrome. Settings becomes a quieter student page.

Outcome

  • Clicking a verified assignment opens a paper sidebar with details, a start action, prior Inky work, and a talk field.
  • Inky’s desk opens that sidebar on the live school page and the current run. Week-view Inky matches the run and reopens the desk.
  • Feedback sits in a compact week note and in Settings. Settings uses Inky / school / privacy / account copy.

Data shape

One renderer panel: closed, assignment, or desk. One derived showingLiveDesk value means the sidebar is on the live run. Electron still owns tasks, permission, and execution. startAssignment(taskId) refuses before enqueue if a run is live, otherwise enqueues, steers, and starts that task. The guest page uses measured sidebar slot bounds.

Reuse or delete

  • Reuse task detail, manager talk, desk activity, and settings persistence.
  • Delete the Library chrome screen and the full-page desk takeover of the week board.
  • Do not add a second queue or a second Inky state machine.

Pass

  • Week board stays up during work. Sidebar shows the selected assignment or the live desk.
  • Make Inky do this calls the new start path. Talk-about-this uses the existing manager with assignment context.
  • Library is gone. Settings sections still save the same records.

Fail

  • Work still replaces the week board, Library remains in chrome, or Inky reports a false state.
  • Seeded assignments appear when a scan is empty or partial.
