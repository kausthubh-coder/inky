WP-12 · approved continuous-build dossier

The first time Studi feels like one product, not a control panel.

This package turns the proven auth, agent, browser, scan, queue, lifecycle, and telemetry boundaries into the complete desktop flow: guided setup, truthful weekly dashboard, command bar, an active-only desk, settings, task evidence, and feedback.

Observable journey

Clerk gate→meet Studi→connect agent→school sign-ins→visible scan→weekly dashboard→command→active desk→review or saved artifact

Renderer ownership

  • React owns navigation, forms, disclosure, selection, and presentation only.
  • Electron projections remain the source of auth, runtime, scan, assignment, manager, lifecycle, browser, permission, and telemetry truth.
  • One top-level StudiApp composes focused screens; avoid a client state framework or duplicate state machine.
  • The existing clean-room renderer may be simplified and split. It is not the legacy dashboard prohibited by the master plan.

Primary surfaces

  • Onboarding: conversational setup transcript with discrete student replies and evidence-backed steps for name, runtime, school URL, visible sign-in, schedule, first scan, linked-system handoffs, and completion.
  • This week: greeting, scan freshness, command bar, five-day verified assignment grid, honest empty/partial states, and queued/working/review/done desk cards.
  • Studi’s desk: appears only while work is active; shows task plan, live transcript/tool status/evidence, takeover/resume/cancel, and the same visible embedded browser.
  • Settings: defaults, course/pattern/assignment overrides, scan schedule, review and handoff timers, memory visibility, runtime, and telemetry.
  • Task detail: provenance, permission, state history, submission receipt or local answer artifact, and feedback.

Implementation sequence

  1. Define a renderer-facing ProductProjection from existing typed domain state. Add only missing commands for current approved settings, task selection/history/artifact, manager prompt, takeover/cancel, and browser layout mode.
  2. Reshape the current single panel into app chrome with This week, Library/artifacts, Settings, and account. Preserve the established cream paper, dotted texture, hand-drawn dark borders, Shantell headings, Nunito body, and yellow/coral/mint/sky/pink/lavender states.
  3. Build onboarding as one linear conversation whose messages derive from real auth/runtime/profile/browser/scan state. Existing commands perform each action; UI copy never marks a step complete before the projection does.
  4. Build the weekly dashboard exclusively from verified local assignments. Group by local day and due time; show provenance and partial coverage. Empty scans stay empty—never seed demo schoolwork.
  5. Wire the large command bar to the single manager session. A command may select/suggest an assignment, change queue order, ask for clarification, or start work only through manager events.
  6. Render desk cards from manager/lifecycle state. When no task is active, no desk sidebar/browser work surface is mounted. When active, switch the Electron browser layout to the task view and show transcript, current tool, evidence, queue, takeover, resume, cancel, review timer, and receipt/artifact actions.
  7. Add focused settings backed by versioned local records: global default, course/pattern/assignment permission overrides, scan cadence, review timer, handoff timer, memory visibility, runtime model, and telemetry. Reuse the permission resolver; do not implement submission policy in React.
  8. Add task detail/artifact and local Library views. Open Markdown artifacts through the existing artifact service; show only metadata/content the user requests, never preload all local files.
  9. Add feedback from gate, dashboard, task, and scan-gap contexts through the existing narrow Convex feedback command.
  10. Add a deterministic app-control scenario for UI states only, then drive the same screens with real Pi and a controlled LMS page. No conditional UI path may know which backend supplied the projection.
  11. Run rendered Electron QA at common desktop sizes, keyboard/focus checks, truthful empty/error/handoff/restart states, and one full user flow. The exact original screenshot is unavailable, so report visual consistency against the repository’s durable design system rather than claiming pixel fidelity.

Truth and interaction rules

  • Never show done, submitted, verified, or scanned without retained evidence.
  • Every failure names what owns the problem and what the student can do next.
  • Agent status comes from persisted run/tool events, not timers or animated copy.
  • Takeover never swaps to a fake screenshot; the embedded browser remains the source.
  • Attempt-only never exposes an auto-submit shortcut. Permission is resolved again outside React.
  • Closing the window still hides Studi; active work remains visible from tray reopen.

Explicit exclusions

  • No learning sessions, tutoring curriculum, marketing website, admin console, billing checkout, collaborative devices, or mobile layout.
  • No generic router/state store/design-system package, page-builder abstraction, transcript protocol, or duplicate workflow state.
  • No seeded assignments in production, LMS-specific UI, invented grades, or optimistic progress.
  • No pixel-perfect claim against the expired temporary reference image.

User-like test

Start from a clean app profile with a real approved Clerk test user. Complete runtime and controlled school sign-in handoffs, run the visible first scan, land on the populated weekly dashboard, issue a manager command, watch the active-only desk and embedded browser, take over and resume, reach review/artifact state, change a permission/schedule/telemetry setting, restart, and verify every state remains truthful. Repeat the core route with deterministic app control only to make rare failure/handoff states inspectable.

Pass conditions

  • The normal first-run journey reaches a verified dashboard without seeded school data or renderer-invented status.
  • Command bar, manager queue, active-only desk, live browser, transcript/tool evidence, handoff, review, receipts, and artifacts work through typed boundaries.
  • Settings persist locally and change permission/schedule behavior through their existing owners.
  • Real Pi + controlled LMS and deterministic app control drive the same React screens with no backend-specific branch.
  • Keyboard, focus, error/empty/partial, restart, and tray-reopen flows remain usable at supported desktop sizes.
  • Existing auth, telemetry, contracts, storage, agent, Electron, build, and protected Sites gates remain green.

Fail conditions

The package fails if React invents domain state, active desk/browser chrome remains when idle, a partial scan looks complete, demo assignments enter production, settings bypass the permission resolver, live browser is replaced by a fake image, or visual polish hides the actual next action.
