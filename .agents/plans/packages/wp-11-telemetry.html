WP-11 · approved continuous-build dossier

Useful product evidence, with no schoolwork hiding inside it.

Studi will send a small vocabulary of product events, redacted failures, and fully masked renderer replay to the connected PostHog project. One outbound boundary makes the privacy rule inspectable. The embedded school browser remains completely outside PostHog.

Observable outcome

Student uses Studi→typed event builder→allowlist + redaction→local inspector→PostHog

A tester appears as one Clerk identity across desktop events and masked Studi replay. Turning analytics off stops both main-process capture and renderer replay. Sign out resets the identity.

Small ownership model

  • TelemetryService in Electron main owns event schemas, redaction, opt-in state, a bounded local inspector, posthog-node, and shutdown flush.
  • RendererTelemetry owns only posthog-js in the React renderer. It receives non-secret config and identity state; it never runs in the school WebContentsView.
  • Clerk subject is the shared distinct ID after approval. A local anonymous device ID covers the signed-out gate and is aliased only when appropriate.
  • The auth coordinator’s existing reset hook clears both SDK identities on sign-out.

Allowed vocabulary

  • Product flow: auth gate, onboarding step, scan started/finished, dashboard viewed, queue/task transition, handoff, review, fallback, setting changed, feedback sent.
  • Operational facts: app version, platform, opaque run/task IDs, durations, counts, state names, tool names, model/provider name, token/credit counts, stable error codes.
  • Never raw prompts, model output, tool arguments/results, page text/HTML, screenshots, cookies, headers, credentials, school URLs, course or assignment titles, answer artifacts, memory, or local file content.

Implementation sequence

  1. Use the connected studi / Default project and its public project key. Put public endpoint configuration in ignored environment input and inject only the values each process needs.
  2. Define one closed event map with per-event fields. Builders construct new allowlisted objects; no generic object spreading or arbitrary metadata bag crosses the boundary.
  3. Add central sanitizers for errors and known identifiers. Reduce URLs to approved origin category or a one-way hash; strip query/path, credentials, headers, canary strings, file content, and stack-local values before enqueueing.
  4. Implement the main TelemetryService with opt-out, identity, capture, exception, a small scrubbed inspector ring, and awaited shutdown. Keep SDK retry/batching behavior direct; do not create a second queue framework.
  5. Initialize posthog-js only from the React renderer with autocapture restricted to useful clicks, all text and inputs masked in replay, console/network capture disabled, and persistence appropriate for a desktop renderer. Never inject preload or scripts into the school view.
  6. Wire the current auth identity/reset seam and a handful of existing high-value lifecycle boundaries. Do not instrument every function or duplicate task event persistence.
  7. Add settings for analytics/replay opt-out, local telemetry inspector, and time-bounded beta debug capture. Debug mode may add redacted summaries from the same allowlist; it never sends raw agent payloads and must show a persistent visible indicator while enabled.
  8. Capture renderer and main failures through the same sanitizer. Preserve normal app error behavior.
  9. Run a canary interception test at the outbound adapter, then launch the real app, produce one signed identity’s events and masked replay, opt out, and confirm capture stops. Query the connected project for the emitted event keys and replay linkage.

High-value cases

  • A payload containing fake cookie, authorization header, password, school URL, page HTML, prompt, and answer text reaches the interceptor with none of those values.
  • The school WebContentsView has no PostHog object, script, requests, or replay session.
  • Renderer replay contains layout and interaction timing but masks every text/input value.
  • Main and renderer events share the same approved Clerk subject; sign-out resets both.
  • Opt-out stops new events and replay immediately; restart preserves the preference.
  • Shutdown awaits the main client flush without blocking normal tray lifecycle indefinitely.

Explicit exclusions

  • No dashboards, feature flags, experiments, surveys, billing analytics, warehouse, or generic OpenTelemetry stack.
  • No raw AI observability payloads, prompt storage, agent transcript upload, or school-browser replay.
  • No automatic instrumentation of every task transition; only decision-useful events.
  • No custom analytics transport, retry database, or schema-generation framework.

Real test

Use the production Electron app to move through the signed-out gate, one approved identity when the WP-10 handoff is available, settings, a controlled queue/agent action, and sign-out. Inspect the renderer and school view separately. Query PostHog for the exact event, distinct ID, and replay association; intercept one canary run locally; opt out and prove no later event arrives.

Pass conditions

  • Connected PostHog project receives useful typed product/error events and a fully masked Studi-renderer replay tied to one tester identity.
  • Canary values never appear in intercepted or remote payloads; school browser produces no PostHog traffic.
  • Opt-out and sign-out affect both processes immediately and survive restart where applicable.
  • The inspector displays only the final scrubbed envelopes actually eligible for upload.
  • Existing auth, contracts, storage, agent, Electron, build, and protected Sites gates remain green.
  • One read-only reviewer rates the green diff at least 8/10 for clarity, subtraction, and privacy-boundary legibility.

Fail conditions

The package fails if arbitrary metadata can be spread into capture, a secret or school value crosses the adapter, replay records the school view or readable student text, opt-out leaves one SDK active, sign-out keeps the Clerk identity, or telemetry code adds more machinery than product evidence.
