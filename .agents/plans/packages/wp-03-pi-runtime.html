WP-03 · approved by standing plan

Prove one real Pi session without building a provider framework.

WP-03 gives later manager and browser packages one small agent boundary. It proves Pi session creation, safe custom tools, normalized events, provider readiness, interruption, compaction, and local resume. It adds no agent UI or school automation.

Outcome

Electron code can create or resume a real Pi AgentSession, subscribe once through a Studi-owned session object, run a harmless custom tool with all built-in file and shell tools disabled, and report provider readiness without exposing credentials.

Value path

WP-06 can later create the continuous Studi manager without knowing Pi event shapes or credential storage. Onboarding can show whether a supported provider is ready or needs login.

Core shape

  • AgentRuntime creates or resumes one AgentSession.
  • AgentSession owns its Pi subscription and exposes prompt, compact, abort, replace, and dispose.
  • AgentRunEvent is one discriminated union for text, tool lifecycle, retry, compaction, abort, and terminal state.
  • ProviderStatus contains only provider identity, usable state, supported login methods, and a user-facing reason. No tokens, headers, or credential paths cross the boundary.

Reuse or delete

  • Reuse WP-01 Zod boundary validation and WP-02 local data root conventions.
  • Use Pi's own persistent session manager. Store only its opaque session ID and path linkage in Studi later.
  • Keep the current Electron self-test as the runtime check and extend it only if that stays readable.
  • There is no active Codex CLI execution path to preserve.

Do not build

  • No generic multi-provider adapter system.
  • No manager or worker orchestration.
  • No browser, school, memory, queue, auth UI, or renderer controls.
  • No copying Pi session transcripts into SQLite.
  • No tests that make paid model calls.
  • No hand-written Pi credential parser.

Implementation units

  1. Add the pinned Pi SDK package and compile it inside the Electron main-process build.
  2. Define the narrow Studi runtime contract and normalized event union.
  3. Implement Pi session creation with built-ins disabled and one harmless studi_probe tool.
  4. Normalize Pi events and rebind the subscription when the underlying session is replaced.
  5. Report provider status through ModelRuntime without reading credential files directly.
  6. Add a deterministic fake for consumers and tests. Use an injected deterministic model only if needed to drive the real Pi session without a paid call.
  7. Perform the subtraction pass and retain one concise runtime receipt.

Risks worth proving

  • The SDK or its native assets fail under Electron 37 on Windows.
  • Pi built-in filesystem or shell tools remain enabled.
  • Session replacement silently loses event subscriptions.
  • Provider reporting leaks secrets or treats missing auth as a crash.
  • Pi and fake event ordering drift.

Proof

  • npm run typecheck and the existing package gates.
  • A focused agent-runtime test using no paid provider.
  • A real Electron self-test that instantiates the Pi runtime boundary.
  • A receipt showing the custom tool lifecycle, terminal event, replacement subscription, and redacted provider status.

Pass when

The installed app code creates an actual Pi session, exposes only studi_probe, normalizes the required lifecycle events, survives session replacement, reports missing or available provider auth safely, and resumes a local session. All checks run without a paid model call.

Fail when

The implementation shells out to Codex, invents a provider framework, enables Pi file or shell tools, copies secrets into evidence, loses subscribers after replacement, depends on a live paid call, or changes protected Sites source files.

Debug order

Start with Pi package loading, then ModelRuntime, session manager selection, custom tool registration, Pi event mapping, replacement re-subscription, and finally Electron packaging. Stop at the first boundary that does not produce the expected receipt.

Primary source: Pi SDK documentation. Package version observed during planning: 0.84.4.
