WP-07 follow-up · approved package

A linked system is an assignment source, not a profile chip.

The scan agent decides whether a third-party page is a place teachers put homework. Studi records it only when this scan can list the student’s assignments there. Account names and dashboards are not verification, and they must not force a partial board.

Observable outcome

After a real school scan, Jenkins-like submit or profile pages that cannot list homework are omitted. A catalog the agent can inventory becomes a verified linked system. Login still pauses the scan only when it blocks that list.

State owner

SchoolScanCoordinator still owns recording. LinkedSystem stays needs_user | verified. Assignments already carry sourceTarget; verified inventory is an origin match on those current-scan rows, or visible empty-index text.

Reuse and delete

  • Keep one general scan_record_linked_system tool and snapshot grounding.
  • Keep login-required language for needs_user.
  • Delete verified login-phrase markers: signed in, logged in, log out, my account, account menu, profile menu.

Named risks

  • A dashboard or “Signed in as …” page cannot persist verified.
  • A listed assignment from the same origin can.
  • A signed-out or login-required page still cannot.
  • A non-catalog autograder is omitted and does not force partial.
  • A login-blocked catalog still hands off as needs_user.

Do not grow

  • No per-LMS adapter or Jenkins/WebAssign completion path.
  • No linkedSystemId column and no second state machine.
  • No schema migration.

Pass

The focused coordinator check proves reject-name-only, list-then-verify, signed-out rejection, and omit-non-catalog success. A later live retry of the real scan must not banner that the state recorder rejected account text.

Fail

The package fails if a name or dashboard heading can mark a linked system verified, old rows count as current inventory, or an LMS-specific scanner replaces the general tools.
