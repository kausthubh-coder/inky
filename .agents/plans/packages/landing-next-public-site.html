Landing Next public site

Outcome
The approved landing mock runs from landing/ as a responsive Next.js app; both email forms write one normalized record through Convex; Clerk is initialized for the shared account boundary; Vercel builds and serves the project.
Value path
A visitor understands Studi in the first screen, explores the four-step product demo, reads the trust promises, submits a campus email, and sees a durable success state without leaving the page.
State and data shape
The demo owns one beat index plus paused/autoplay state in the landing client component. Each waitlist form owns only its input/submission state. Convex owns normalized unique email records in waitlistEmails.
Reuse and delete
Reuse the existing Inky SVG component, Next App Router shell, font loading, public Convex mutation, schema index, Clerk provider, and workspace layout. Replace the old renderer and stylesheet rather than preserving a second landing implementation.
Boundaries
Email is validated by the browser for feedback and again by Convex for trust. The waitlist remains public; no account is required. Clerk initializes the shared site account boundary but does not gate the landing route. Vercel receives only environment references and repository source.
Simplicity constraints
No UI framework, animation library, form abstraction, duplicate demo state machine, API route, or client-side fake persistence. No sign-in surface that was not approved in the mock.
Explicit exclusions
No changes to the Electron app, Clerk waitlist mode, Convex account policy, production data model beyond the existing waitlist table, mission-page redesign, or landing analytics.
Risks and proof
Visual drift: compare desktop and mobile screenshots to the approved HTML. Duplicate or invalid email: run the deployed Convex mutation and inspect the indexed record. Integration drift: typecheck and production-build the Next app with real public environment values. Deployment drift: open the Vercel URL and submit from the live page.
Pass when
The app builds cleanly, all four demo beats work at desktop and mobile widths, both forms show the same durable success path, duplicate submission is idempotent, Clerk and Convex providers initialize without gating the page, and Vercel reports a ready deployment.
