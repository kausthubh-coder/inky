Verified · WP-02 · cycle 5

Make local state durable without making storage clever.

WP-02 adds one versioned SQLite database, append-only task events with rebuildable projections, atomic Markdown artifacts, backup and restore, and clear corruption errors. It does not add an agent, browser controller, scheduler, auth, telemetry, or product UI.

WP-02 conclusionCode walkthroughMaster planEvidence ledger

Observable outcome

Restarting Studi reopens the same validated local records. Task projections can be deleted and rebuilt from immutable events. A failed transaction or artifact write leaves the prior durable state intact.

Package boundary

No legacy JSON import, seeded assignments, cloud sync, encryption layer, full-text search, generic ORM, repository generator, or speculative query API.

Driver decision

Use bundled node:sqlite

Electron 37 reports Node 22.21.1. That runtime includes DatabaseSync, transactions, integrity checks, and the backup API. The driver stays behind one small module and fails explicitly if Electron loses the API.

Why not better-sqlite3 here

It is capable, but Electron's official guidance requires ABI-specific rebuilds for native modules. Its own Electron guide also requires rebuild and ASAR unpacking. WP-02 gains no product behavior from that packaging work.

This is a deliberate update to the master plan's earlier preference. A real Electron test must open, write, back up, and reopen the bundled database before the package can pass. Sources: Node SQLite API, Electron native-module guide, and better-sqlite3 Electron notes.

Database is authoritative for operations

Repositories parse on write and again on read. JSON keeps the WP-01 record exact; indexed columns support the known queue, course, state, and due-date queries.

Markdown is authoritative for editable agent context

Frontmatter is versioned and typed. Content stays human-editable. Writes use a sibling temporary file, flush it, then rename it into place.

Core invariants

  1. Migration steps run in one transaction and record their version only after success.
  2. A database newer than this app fails closed. Corruption never triggers silent recreation.
  3. Appending a task event and updating its projection is one transaction. Both commit or neither does.
  4. Event IDs and task sequence numbers are unique. Projection revision must advance exactly as the event states.
  5. Deleting projections and replaying events produces the same validated task state.
  6. Every repository accepts and returns WP-01 types. Raw SQL rows and unparsed JSON do not escape the storage package.
  7. Artifact paths derive from validated kind and opaque ID. Caller-controlled traversal never reaches the filesystem.
  8. A failed artifact write leaves the old target readable and cleans its owned temporary file when possible.
  9. Backup uses SQLite's backup operation and copies artifacts into a self-contained directory. Restore validates before replacing active data.

Implementation order

  1. Add a complete task-origin event only if replay cannot be correct without it. Reuse every other WP-01 contract.
  2. Create the SQLite driver and a transactional, ordered migration registry.
  3. Add assignment, permission-rule, run, task-event, and projection repositories around prepared statements.
  4. Implement atomic event plus projection append, optimistic revision checks, and projection replay.
  5. Add typed Markdown frontmatter and atomic read/write behavior for the four artifact kinds.
  6. Add integrity diagnostics, database plus artifact backup, validation-first restore, and interrupted-operation recovery.
  7. Wire store open and close into Electron without adding public IPC.
  8. Run focused storage tests, full WP-01 regression, protected Sites checks, and a real Electron storage round trip.

Pass when

  • A fresh directory migrates to schema 1 and reopens without extra rows or migration work.
  • Known assignment, permission, run, task-event, and projection queries round-trip validated records.
  • An injected projection failure leaves neither the event nor projection update committed.
  • Projection deletion and replay reconstruct the same task and reject an invalid event stream.
  • An artifact rewrite is atomic, traversal is rejected, and malformed frontmatter returns a typed diagnostic.
  • A backup validates and restores into a fresh location with the same records and artifacts.
  • Corrupt and too-new databases fail without being overwritten.
  • The real Electron runtime opens node:sqlite, writes and reopens data, creates a backup, and removes only its owned self-test directory.
  • WP-01, foundation, Sites, and Electron gates stay green.

Fail when

  • A crash can commit an event without its projection or a projection without its event.
  • Opening corruption silently creates an empty database.
  • Restore mutates active data before validating the backup.
  • Any repository returns unvalidated JSON or accepts a caller-selected table or SQL fragment.
  • Artifact IDs can escape the owned directory.
  • Prototype JSON, demo assignments, passwords, cookies, page HTML, or browser state enter the new store.
  • The package introduces cloud sync, renderer database access, an ORM, or a general-purpose abstraction with no current caller.
